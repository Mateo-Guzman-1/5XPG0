# Energy notebook

All energy numbers of the keyword spotter are kept here: where the power numbers come from (raw
Vivado values), how energy is calculated from them, how the estimate was validated, and the results
per design. Start here before quoting any energy number. The plan behind it is
[PLAN_SYNAPSE.md](PLAN_SYNAPSE.md) (experiments S0–S5).

Application this is optimised for: an **always-on smart-home wake-word detector**. One window of
audio arrives every 250 ms, so inference must finish within 250 ms, and the detector runs all day,
so its average power is what matters.

## 1. Source of the power numbers (S0)

- **Tool:** Vivado 2026.1 `report_power` on the **routed** design. The estimate is vectorless: no
  simulation activity, Vivado's default toggle rate is 12.5 %. Settings: 25 °C ambient, typical
  process, Vivado's default board and airflow. Vivado rates its own confidence as **"Medium"**: the
  activity of the internal nodes is not simulated.
- **Two fabrics** (two FPGA designs). Both have the same clock (FCLK0, 100 MHz) and the same 256 KiB
  BRAM:

  | Fabric | Hardware | RTL source |
  |---|---|---|
  | **RV32IM** (`base`) | PicoRV32 without the accelerator | Commit `714db5c`, the source of `deploy/keyword.bit` (RTL identical to `024610e`) |
  | **RV32IM + kdot** (`kdot`) | PicoRV32 with the kdot coprocessor | `HEAD`; all six RTL files match the hashes in `deploy/manifest.json` |

- **How they were built:**
  - `research/tools/power/vivado_power.tcl` runs the unchanged `vivado/build.tcl` in a `git archive`
    copy (under `build/vivado_power/`, never in the tracked tree), then writes the reports.
  - Only a tool-environment detail differs. Vivado 2026.1 passes the board-file path to its
    child runs without quotes, and the space in "Semiconductor Technology" breaks it. So the
    vendored PYNQ-Z2 board files are copied to a folder without spaces under `%TEMP%`.
  - The release bitstreams were made with Vivado 2025.2. The rebuild uses the same RTL, so
    utilization is within 0.6 % of the release: base 2,683 LUT / 2,578 FF / 64 BRAM / 6 DSP
    (release 2,699 / 2,588 / 64 / 6); kdot 2,881 / 2,735 / 64 / 8 (release 2,879 / 2,735 / 64 / 8).
  - Timing is met: worst slack +0.141 ns (base) and +0.782 ns (kdot).
  - The rebuilt bitstreams are **not** loaded on the board; the board keeps running the release files.
- **Files:**
  - raw reports: `results/S0/vivado/<fabric>/power*.rpt` (plus utilization, timing, DRC);
  - parsed: `results/S0/power.json` (`research/tools/power/parse_power.py`).

**Sensitivity to Vivado's activity assumption** (`power_toggle6.25.rpt`, `power_toggle25.rpt`):
halving or doubling the default toggle rate changes P_PL,dyn by at most 2 mW (base 0.277–0.279 W,

both ports in every clock cycle, whatever the activity.

## 2. From power to energy

| Symbol | Meaning |
|---|---|
| f | 100 MHz, the PL clock |
| T | 0.25 s, the time between two windows |
| C_mean, C_max | cycles of one inference, measured on the board (only bit-exact runs; `bench_board.py`) |
| P_PL,dyn | dynamic power of the programmable logic = dynamic − PS7 |
| P_PL,stat | static power of the PL supply rails (sum of V × static current); the PS rails are left out |
| P_core,dyn | dynamic power of `u_soc` (PicoRV32, kdot and the 256 KiB BRAM) |
| P_infra,dyn | the rest of the PL: AXI interface to the ARM, clock buffers |

The ARM processing system (PS7, 1.258 W, plus 0.062 W static) is the *host*. It records audio and
runs Linux; it is not part of the detector, so it is reported raw but not attributed. On a real
smart-home device this role is played by the main processor, which is mostly asleep.

| Quantity | Formula | Meaning |
|---|---|---|
| Energy per inference | E_inf = P_PL,dyn × C_mean / f | Dynamic energy of one inference: what the network design changes |
| All-in energy per inference | E_inf,all = (P_PL,dyn + P_PL,stat) × C_mean / f | Including the static energy during the inference |
| Latency | t_max = C_max / f | Must stay below 250 ms |
| **(a) Busy-polling** | E_win = (P_PL,dyn + P_PL,stat) × T | Today's firmware: the core never stops; the same for every model |
| **(b) Clock-gated idle** | E_win = (P_PL,stat + P_infra,dyn) × T + P_core,dyn × C_mean / f | Core clock stopped between windows |
| **(c) Clock scaled to the deadline** | E_win = P_PL,stat × T + P_PL,dyn × 1.1 C_max / f | FCLK0 lowered to f_min = 1.1 C_max / T (10 % slack); dynamic power is proportional to f, and FCLK0 is settable at run time on PYNQ |
| Average power | E_win / T | Per scenario |
| Energy per synaptic operation | E_inf / (executed synaptic multiply-adds) | Input layer N_in × H (or the non-zero count) + output layer 2H |

Vectorless power does not depend on what the core computes. Within one fabric, the energy of two
models therefore differs only through their cycle counts, which are measured exactly. Vivado's
uncertainty affects the absolute values and the comparison between the two fabrics, not the
ranking of models on one fabric.

What it shows:
- **Energy per inference grows linearly with the number of neurons.** RV32IM: 259 µJ per neuron
  (fit for H ≥ 32, R² = 1.000000). kdot: 11.4 µJ per neuron (R² = 0.9999). kdot uses 22–37× less
  energy per inference.
- **The memory, not the processor, dominates the PL power.** The 256 KiB block RAM is 0.251 of the
  0.278–0.282 W PL dynamic power (89–90 %). The PicoRV32 is 0.011 W and kdot 0.005 W. The BRAM is
  read on both ports in every cycle, so this power does not depend on the model's size.
- **With today's busy-polling firmware, the network does not change the energy at all.** Every
  window costs 363 mW (RV32IM) or 367 mW (kdot) × 0.25 s, whatever the size.
- **Network savings only appear if the core stops between windows:**
  - Clock-gated: RV32IM 101 → 189 mW for H = 8 → 95; kdot 93.2 → 97.3 mW.
  - Clock scaled to the deadline: RV32IM 94 → 194 mW; kdot 85 → 90 mW.
- **With kdot, average power is set almost entirely by static power plus the interface** (93 mW).
  The network itself adds 0.2–4.4 mW.
- **Energy per synaptic multiply-add:** RV32IM about 337 nJ; kdot 9–15 nJ. These are all-in soft-core
  numbers (fetching, memory and control included). For comparison only as an order of magnitude:
  neuromorphic chips report tens of pJ per synaptic event (values to be verified from the papers
  before citing).

## 5. Limits of these numbers
- **Estimates, not measurements.** Vectorless estimates at "Medium" confidence. They were validated
  once with a USB meter (section 3), but that meter measures the whole board, ARM included.
- **Rebuilt bitstreams.** The power comes from a Vivado 2026.1 rebuild of the same RTL. Placement
  and routing differ from the 2025.2 release bitstreams that produced the cycle counts.
- **Scenarios (b) and (c) are calculations.** Neither clock gating nor clock scaling is implemented
  in the firmware or the server (the server checks for 100 MHz). Scenario (c) assumes that power is
  proportional to frequency at a fixed voltage.
- **Board-level energy is much larger.** The PS (1.3 W, the "host") and the rest of the board (DDR,
  Ethernet, regulators) consume far more than the PL. These numbers describe the detector logic only.
