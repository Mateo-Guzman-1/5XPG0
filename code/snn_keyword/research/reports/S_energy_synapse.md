# S0–S5 — Energy-aware network size and synapse optimisation

*Date:* 2026-10-17 · *Branch:* Pedro · *Plan:* [PLAN_SYNAPSE.md](../PLAN_SYNAPSE.md) · *Energy method and raw
values:* [ENERGY.md](../ENERGY.md) · *LaTeX section for the report:* `reports/latex/size_synapse/`
(`section.tex`, `figures/`, `tables/`; `standalone.tex` compiles it on its own).

## Summary

| | |
|---|---|
| **Question** | For an always-on keyword spotter on the PicoRV32, how do the number of synapses (neurons, fan-in) and the bits per synapse trade energy per inference against quality, within 250 ms and 144 KiB? |
| **Energy method** | Vivado 2026.1 `report_power` of both fabrics × board cycle counts. Validated against a USB meter on a group design: Vivado's PL estimate is 7 % below the measured board increase. |
| **Size (S1)** | 259 µJ (RV32IM) and 11.4 µJ (kdot) per neuron per inference. Quality is flat from 16 neurons on. With the deployed busy-polling firmware the average PL power is 363/367 mW for every size. |
| **Precision (S2)** | QAT keeps the validation F1 within the seed spread down to 4 bits; 3 bits lose a little, 2 bits fail. Rounding a trained model loses more. On RV32IM fewer bits cost *more* energy: the packed loop is 14.1 / 18.3 / 28.1 mJ at 8 / 4 / 2 bits against 12.5 mJ for the release loop. |
| **Count (S3)** | Large-pruned beats small-dense at equal synapses (6,144: 0.727 vs 0.643). 8 % of the synapses keep 0.727 (vs 0.740). On RV32IM energy follows the non-zero count (7.4× less at K = 64); kdot gains nothing. |
| **Neuron update (S4)** | Exact 12-threshold table, bit-exact: kdot cycles fall 2.7–3.4×, RV32IM cycles 2–3 %. |
| **Choice (S5)** | 48 neurons, 8-bit weights, kdot + table: 165 µJ and 0.59 ms per window, 72.4 KiB. Against the deployed model: 6.7× less energy, half the memory, test F1 0.789 vs 0.782. The pooled-sd sensitivity rule gives the same choice. |

## Hypotheses (written before the experiments) and outcome

| Hypothesis | Outcome |
|---|---|
| H1: energy ∝ cycles; synapses ≥ 95 % of RV32IM cycles, ≤ ~15 % with kdot | **Confirmed.** 97 % on RV32IM; 19–27 % with kdot (synapses + output layer). |
| H2: quality kept down to 4 bits, fails at 2; RV32IM cycles change < 10 % | **Quality part confirmed; cost part refuted.** Packed loops cost 13–125 % more energy than the release loop; even the 16-bit control costs +30 %. |
| H3: large-sparse ≥ small-dense at equal synapses; RV32IM ∝ non-zeros; kdot gains nothing | **Confirmed.** |
| H4: exact LIF table cuts kdot cycles ≥ 2×, RV32IM < 5 % | **Confirmed:** 2.7–3.4× and 2–3 %. |
| H5: busy-polling energy independent of the network; savings need idling; choice = small dense kdot + table | **Confirmed.** The choice is 48 neurons; 16 neurons is cheaper but below the quality bar. |

### Selection
Pre-registered rule: mean validation F1 ≥ best − sd(best), t_max ≤ 250 ms, memory ≤ 144 KiB; then
the lowest E_inf. Details in `results/S5/choice.json`.
- **Rule as written:** the best design is H48 8-bit (0.7452 ± 0.0047), so the threshold is
  0.7405. Five designs qualify, and the rule chooses **H48 8-bit on kdot + table**.
- **Fragility:** the E2 H48 16-bit model misses the bar by 0.0007, because the best design has a
  small sd.
- **Sensitivity check:** with the pooled sd (0.020) the threshold is 0.7255. 23 designs qualify,
  and the choice is the same.
- **Bit width does not matter here:** the 6- and 4-bit versions qualify at the same energy (kdot
  stores int16 whatever the precision).

### Chosen design against the deployed model
`results/S5/table_choice.md`.
- **Cost:** 165 vs 1,103 µJ per inference, 0.59 vs 3.96 ms worst case, 72.4 vs 143.3 KiB.
- **Quality:** test F1 0.789 ± 0.010 vs 0.782; live "Sheila" (2 of 3) 65.6 vs 60.9 %; other words
  0.36 vs 0.33 %.
- **Weak spot:** "shee" + other word is accepted 40.1 vs 33.1 % of the time.
- **Average PL power at 4 windows/s:** busy-poll 367 = 367 mW; clock-gated 93.6 vs 97.3 mW; clock
  scaled 85.7 vs 89.9 mW. The static power plus the interface set a 93 mW floor.

### Notes on the data
- **No usable models:**
  - **2-bit rounding only, H48:** stream tuning fails because every weight rounds to zero.
  - **H95 at K = 512:** does not fit the model memory in the 32-bit sparse format (194,560 B).
- **Pruned models on dense kdot:** 200,021 cycles (H48 K64) vs 203,253 dense. kdot streams the
  zeros too.

## Threats to validity
- **Energy is estimated, not measured.** Vivado vectorless estimates at "Medium" confidence. They
  were validated once, on a different design and at board level (7 %).
- **The power comes from rebuilds.** The power-analysed designs are Vivado 2026.1 rebuilds of the
  release RTL; the cycles come from the 2025.2 release bitstreams.
- **Two scenarios are calculations.** Clock gating and clock scaling are not implemented.
- **Small samples.** 3 seeds and 212 test positives; differences within the seed spread are not
  interpreted.
- **One implementation per format.** One packed and one sparse loop implementation; other code
  could shift their cost.
- **Near misses are synthetic.** They are measured with edited recordings and two computer voices,
  not with real speakers (E1 deferred).
